# Codelink 晋级赛

Codelink 上午场使用 `codelink-qualifier` 比赛类型。选手自由选题，每道题的计分名额只授予最先通过该题且尚未晋级的若干名选手，获得名额后取得该题对应的积分。累计达到 3 分直接晋级下午场，参加 [Codelink 淘汰赛](./codelink-bracket.md)。上午场结束后，先从 2 分选手中补位，再从 1 分选手中补位，补足 16 席。

## 启用插件

Codelink 晋级赛和淘汰赛插件随每个发布包提供，但默认不加载，需手动启用。在每台服务器节点的发布包目录中运行以下命令，然后在管理后台的**插件**页面单击 **Reload All**。

```bash
./enable-plugin.sh codelink-qualifier codelink-bracket
```

也可以在安装时启用，即运行安装脚本时设置 `BROCCOLI_PLUGINS`。`install.sh` 和 `install-native.sh` 的用法相同。

```bash
BROCCOLI_PLUGINS="codelink-qualifier codelink-bracket" ./install.sh server
```

在开发环境中，从仓库构建并安装这两个插件。

```bash
pnpm --filter @broccoli/web-sdk build
just build-plugin plugins/codelink-qualifier --install
just build-plugin plugins/codelink-bracket --install
```

## 创建比赛

1. 在比赛编辑页面，将比赛类型设为 `codelink-qualifier`，并设置上午场的开始时间和结束时间。
2. 添加题目。每道题需配置测试数据，以及相应的评测器、检查器和语言插件。
3. 为全部选手报名。榜单只显示已报名的选手。

## 设置规则

在管理后台打开该比赛的 **Configure** 对话框，选择 `codelink-qualifier` 插件的 `contest` 配置。

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| **Expected Problem Count**（`expected_problem_count`） | 20 | 预期题数。实际题数与此不符时，页面显示提示。设为 0 时不检查。 |
| **Scoring Slots per Problem**（`slots_per_problem`） | 2 | 每题名额数，即每道题最多有几名选手获得计分名额。 |
| **Points to Qualify**（`solves_to_qualify`） | 3 | 直接晋级所需的积分，配置键保留原名称。 |
| **Advancement Places**（`advancement_slots`） | 16 | 直接晋级与补位合计的晋级名额数。 |
| **Scoreboard Refresh Interval**（`scoreboard_refresh_seconds`） | 5 | 榜单自动刷新间隔，单位为秒。设为 0 时只能手动刷新。 |

添加 20 道题目。在每道比赛题目的 **Configure** 对话框中，选择 `codelink-qualifier` 插件的 `problem` 配置。**Points per Scoring Slot**（`points`）默认为 1，只接受 1 或 2。将其中四道题设为 2 分，其余十六道题保持 1 分。分值属于当前比赛，同一道题在其他比赛中可以使用不同分值。

每题名额数、晋级积分和晋级名额数的取值范围为 1～1000，预期题数为 0～1000，刷新间隔为 0～3600，均为整数。预期题数只用于显示提示，不会强制要求题目数量或各分值的题目数量。

已有配置保留原值。复用旧比赛时，请将预期题数改为 20、晋级积分改为 3，并确认晋级名额数为 16。

配置应在开赛前完成。修改保存后，下一次刷新时生效，榜单按新配置重新计算，无需重新构建插件。

## 晋级规则

名额按提交时间先后授予，规则如下。

1. AC 提交按提交时间排序；提交时间相同时，提交 ID 小者在前。评测完成的先后不影响排序。
2. 同一选手在同一题上只计第一次 AC。
3. 选手未晋级时，该次 AC 占用该题的一个空余名额；该题名额已满时，不再授予名额。
4. 获得名额时取得该题的完整分值，累计积分达到或超过晋级积分后直接晋级，已获得的名额和积分保留。此后的 AC 不占用名额，也不改变晋级时间。

默认晋级门槛下，1 分加 2 分、三个 1 分均可晋级；两道 2 分题，或先取得 1 分加 1 分再取得 2 分，均以 4 分晋级。此计算不为直接晋级选手分配下午场种子排名。

未获得名额的 AC 不计积分。已晋级的选手不再参与名额分配，其后通过该题的选手依次递补。以默认配置为例，结果如下表所示。

| 事件 | 结果 |
| --- | --- |
| Alice 获得 1 分题 A 和 2 分题 B 的名额 | Alice 以 3 分晋级，保留这两个名额 |
| Alice 随后通过 C 题 | 显示该 AC，C 题的 2 个名额仍空余 |
| Bob、Carol 随后通过 C 题 | 两人各获得 C 题的 1 个名额 |
| Dave 随后通过 C 题 | 显示该 AC，不授予名额 |

只统计上午场时间内的提交。截止前提交、截止后才完成评测的代码，仍可获得名额。练习提交及比赛时间外的提交不占用名额。评测出错或题目缺少测试数据时，不判为 AC。

## 比赛进行中

**排行榜**显示总积分、获得计分名额的题数以及每题分值，按总积分及最后一次实际得分的提交时间排序。上午场结束且评测完成后，页面分别显示直接晋级、补位晋级及未晋级状态，同时列出合计晋级人数和空缺名额。

| 状态 | 说明 |
| --- | --- |
| **直接晋级** | 无论剩余评测结果如何，该选手均已晋级 |
| **评测未完成，无法确认是否晋级** | 尚有评测未完成，其结果可能决定该选手能否晋级 |
| **补位晋级** | 赛后按补位规则获得剩余名额 |
| **未晋级** | 最终名单已确定，该选手未获得名额 |

比赛期间，其他选手不显示直接晋级状态。直接晋级人数和晋级时间只统计**直接晋级**的选手。赛后另行显示补位人数和合计晋级人数。

榜单按配置的间隔自动刷新，上午场结束后继续刷新，直至排队中的评测全部完成。关闭**自动刷新**开关可暂停刷新，单击**刷新**可立即更新。刷新间隔为 0 时，页面显示**仅手动刷新**。

## 评测延迟或出错

出现以下任一情况时，选手显示为**评测未完成，无法确认是否晋级**。

- 该选手本人的提交仍在评测。
- 其他选手更早的提交尚未出结果，且可能占用该选手所需的名额。

仍在排队的提交同样视为未完成。不影响结果的提交不会延迟其他选手的判定，包括名额已满的题目上的提交、已 AC 题目上的重复提交，以及已晋级选手的提交。

晋级结果确定后，即显示**直接晋级**，其他评测是否完成不影响这一判定。在这些评测完成前，该选手的名额和时间仍可能变化。

重测和配置修改生效后，榜单重新计算。未生效的重测不改变正式结果。

## 比赛结束后

上午场结束、所有提交评测完成并核对重测结果后，所有达到晋级积分的选手直接晋级。剩余名额先从 2 分选手中补位，再从 1 分选手中补位。

同分选手按最后一次实际得分的提交时间排序，较早者优先。提交时间完全相同时，提交 ID 小者优先。重复 AC 或未获得名额的 AC 不改变该时间。补位只在上午场结束且评测全部完成后确定，比赛期间选手仍可继续得分。

通过 `GET /api/plugins/codelink-qualifier/contests/{contest_id}/standings` 返回的 `advancement` 字段读取最终名单。上午场未结束或仍有正式提交未完成评测时，该字段为 `null`。

| 字段 | 含义 |
| --- | --- |
| `direct_user_ids` | 达到晋级积分的选手，按用户 ID 列出，不表示种子排名 |
| `reserve_user_ids` | 按补位顺序列出的选手，名额补足后停止选取 |
| `unfilled_slots` | 得分选手不足时仍空缺的名额数 |

同一响应中的 `rows[].score` 为选手总积分，`problems[].points` 为题目分值。`credited` 仍表示获得名额的题数，`qualified_count` 只统计直接晋级人数。

`unfilled_slots` 大于 0 时，志愿者需安排加赛或其他已公布的选拔方式。系统不会自动选择 0 分选手，重测结果生效后会重新计算积分和补位名单。

插件不会自动为选手报名，选出的晋级选手需手动加入 [Codelink 淘汰赛](./codelink-bracket.md)所用的比赛。

单次提交显示的分数只表示该代码是否通过，晋级资格由计分名额和上述最终选拔结果决定。
