# Codelink

上午场晋级赛使用 `codelink` 比赛类型。选手从比赛题集中自由选做，获得足够的计分名额后晋级下午场。每场比赛可以分别设置名额上限、晋级题数和刷新间隔。

## 构建并启用插件

安装 Broccoli 开发依赖后，在仓库根目录运行以下命令。

```bash
pnpm --filter @broccoli/web-sdk build
just build-plugin plugins/codelink --install
```

构建产物包括 `plugins/codelink/codelink.wasm` 和 `plugins/codelink/web/dist` 下的前端包。服务器从配置的插件目录发现该插件，默认目录为 `./plugins`。启动服务器，或在管理界面使用**重新加载所有插件**，即可发现该插件。

在比赛编辑页面选择 `codelink` 比赛类型，设置上午场的开始和结束时间，并添加题目。每道题需要测试数据，以及对应的评测器、检查器和语言插件。将参赛选手加入上午场比赛，榜单只统计已报名的选手。

## 配置比赛

在管理界面打开该比赛的**配置**对话框，选择 `codelink` 插件的 `contest` 设置。

| 配置项 | 默认值 | 作用 |
| --- | --- | --- |
| **Expected Problem Count**（`expected_problem_count`） | 16 | 实际题数与预期不符时显示提示，设为 0 则不检查题数。 |
| **Scoring Slots per Problem**（`slots_per_problem`） | 2 | 每题最多允许多少名不同的合格选手获得计分名额。 |
| **Credited Problems to Qualify**（`solves_to_qualify`） | 2 | 在多少道不同题目上获得名额后晋级。 |
| **Scoreboard Refresh Interval**（`scoreboard_refresh_seconds`） | 5 | 自动刷新间隔，单位为秒，设为 0 则仅手动刷新。 |

题数和计分上限均接受不超过 1000 的整数，两项计分上限至少为 1。刷新间隔接受 0 到 3600 的整数。预期题数仅控制配置提示，实际题目列表和规则中显示的题量始终来自比赛题集。

默认值对应本届上午场的 16 道题、每题两个名额、获得两题名额后晋级。应在开赛前设置这些值。保存更改后，规则说明和已有榜单会在下一次刷新时按新配置更新。配置仅作用于当前比赛。加载新版插件后，更改这些配置无需重新构建插件。

## 分配计分名额

打开比赛的**排名**页面，查看每题按配置提供的计分名额。**概览**页面会显示同一套配置对应的规则。

1. 按最终 AC 提交的提交时间排序。时间完全相同时，提交 ID 较小的在前。评测排队顺序不决定名额归属。
2. 同一选手在同一题上只计算第一次 AC。
3. 选手尚未晋级且题目仍有空余名额时，获得一个名额，每题的名额总数以配置为准。
4. 选手的计分题数达到配置的晋级门槛后晋级，原有名额继续占用。后续 AC 仍会显示，但不再占用新名额，也不改变该选手的晋级时间。

未获得名额的 AC 不计入晋级条件。分配后续题目的名额时，会跳过已晋级的选手，让下一名符合条件的选手获得名额。

使用默认的每题名额和晋级题数时，以下事件会产生对应结果。

| 事件 | 结果 |
| --- | --- |
| Alice 获得 A 和 B 的名额 | Alice 晋级并保留两个名额 |
| Alice 随后通过 C | 显示 AC，C 的两个名额仍然空余 |
| Bob 和 Carol 随后通过 C | 两人各获得 C 的一个名额 |
| Dave 也通过 C | 显示 AC，但没有计分名额 |

仅统计在上午场比赛时间内提交的代码。截止前的提交即使在截止后才完成评测，仍可获得名额。练习提交和比赛时间外的提交不占用名额。评测系统出错或题目没有测试数据时，不会授予 AC。

## 查看晋级状态

榜单按配置的间隔刷新，比赛结束后也会继续刷新，以显示尚在排队的评测结果。可以通过**自动刷新**开关暂停，或点击**刷新**立即更新。刷新间隔设为 0 时，页面显示**仅手动刷新**。

| 状态 | 含义 |
| --- | --- |
| 已确认晋级 | 无论剩余评测结果如何，都能保证该选手晋级 |
| 评测未完成，无法确认是否晋级 | 未完成的评测使该选手的晋级资格尚不能确定 |

榜单只显示这两种判定。可能获得的计分题数仍不足晋级门槛时，不显示判定，可通过**计分题数**查看进度。晋级人数和晋级时间只包含已确认晋级的选手。

待评测提交包括仍在排队、尚未创建判题记录的提交。选手自己的提交尚未评测完成，或更早的提交可能改变其名额归属时，都可能需要等待评测结果才能确定是否晋级。题目名额已确定用完后的提交、同题已 AC 后的重复提交，以及已确认晋级选手的后续提交，不会拖延其他选手的晋级确认。

当能够保证无论待评测结果如何，选手都仍然晋级时，榜单会确认其资格。计算也会考虑待评测结果改变其他选手的晋级时机，从而影响他们是否继续占用后续题目的名额。名额归属和显示时间以当前结果为准，在待评测提交完成前仍可能调整，即使晋级资格已经确认。

已应用的重测和规则更改会重新计算晋级资格。尚未应用的重测不会替换正式结果。将名单用于下午场前，应完成待评测提交并检查重测结果。

单次提交显示的分数表示代码是否通过。晋级资格以 Codelink 榜单的**已确认晋级**判定为准。插件在该榜单中记录晋级状态，不会自动将选手报名到另一个下午场比赛。
