# Codelink 淘汰赛

Codelink 下午场使用 `codelink-bracket` 比赛类型进行单败淘汰，选手通常来自 [Codelink 晋级赛](./codelink-qualifier.md)。对阵规模可选 2 至 128 人，必须为 2 的幂。每个阶段分别设置常规小局上限 BO、晋级所需胜局数 FT 和时长。选手先达到 FT 即赢得本场比赛，剩余常规小局不再进行。打满 BO 局后胜局多者晋级，比分相同时进入附加赛。

## 启用插件

Codelink 晋级赛和淘汰赛插件随每个发布包提供，但默认不加载，需手动启用。在每台服务器节点的发布包目录中运行以下命令，然后在管理后台的**插件**页面单击 **Reload All**。

```bash
./enable-plugin.sh codelink-qualifier codelink-bracket
```

也可以在安装时启用，即运行安装脚本时设置 `BROCCOLI_PLUGINS`。`install.sh` 和 `install-native.sh` 的用法相同。

```bash
BROCCOLI_PLUGINS="codelink-qualifier codelink-bracket" ./install.sh server
```

在开发环境中，从仓库构建并安装这两个插件。

```bash
pnpm --filter @broccoli/web-sdk build
just build-plugin plugins/codelink-qualifier --install
just build-plugin plugins/codelink-bracket --install
```

## 接收小局提醒

在下午场比赛页面单击**开启桌面通知**，并在浏览器中允许通知。开始比赛前单击**测试通知**，检查桌面通知设置。网站需要使用 HTTPS 或 localhost。

每个常规小局或附加赛小局结束后，双方选手都会收到结果。通知说明自己获胜、对手获胜，或时间耗尽且双方均未得分，并显示该小局结束后的比分。

小局结果会保留在页面上，直到手动关闭。当比赛标签页隐藏或窗口失去焦点时，已开启的桌面通知也会显示。单击通知可返回比赛。在其他应用中编写代码时，请保持一个比赛页面打开。切换比赛内页面不会中断提醒，短暂断线后会从小局历史补齐遗漏的结果。首次打开比赛不会重播之前的小局结果。

如果曾拒绝通知权限，请在浏览器的网站设置中允许通知。如果测试通知没有出现，请检查桌面通知和免打扰设置。页面关闭或被浏览器挂起后，无法接收这些提醒。

## 创建比赛

1. 在比赛编辑页面，将比赛类型设为 `codelink-bracket`，并设置下午场的开始时间和结束时间。下午场结束后不再开始任何比赛，时间应足够完成所有阶段。
2. 添加对阵表用到的全部题目。每个阶段需要数量相同的两组题目，以及至少一道附加赛题目。
3. 为计划参与对阵的选手报名。

## 设置规则

打开**比赛主页**，在**操作**区域选择**赛程与对阵**，也可以从后台比赛列表的操作菜单进入。这会打开独立的**淘汰赛管理**页面，拥有 `contest:manage` 权限的工作人员在此配置对阵与各轮赛程。配置完成前，**排行榜**只显示对阵表尚未生成。

1. **选手与种子。** 选择对阵规模，初始值为 16 人，阶段数随规模确定。默认按报名顺序列出已选择的选手。拖动选手调整种子顺序，或单击**随机**。第 1 轮由相邻种子对阵，即 1 号对 2 号、3 号对 4 号，依此类推。移除某名选手后，可从其他已报名选手中补入。
2. **每阶段题目及胜局数。** 设置**常规小局上限（BO）**及**晋级所需胜局数（FT）**，新阶段初始为 BO3 / FT2，因此出现 2 比 0 时打完两局即结束。FT 必须为 1 到 BO 之间的整数。双方各需 BO 道题目，另需至少一道共享附加赛题目。两组题目数量必须相同，常规小局数与附加赛题目数之和不得超过 256。各题目位置初始按比赛的题目顺序填充。配置中的题组不得重复使用题目，季军赛可以显式选择共用决赛题组。
3. **每阶段时间。** 通过日期时间输入框设置每轮的排序开始时间，界面标注当前浏览器的本地时区。该轮所有对局共用完整的 3 分钟排序窗口，随后等待准备时间，默认 30 秒，再同时开始第一小局。每轮分别设置小局基础时长、附加赛时长、共享加时和小局间隔。小局间隔默认 60 秒，从上一小局实际结算时开始计时。后续轮次还要求上一轮全部结束后完成最短休息，初始为 10 分钟。第 1 轮没有轮前休息。常规小局错误提交默认罚时 20 秒，附加赛错误提交不罚时，等待卡住评测的时长默认为 120 秒。
4. **季军赛。** 在下午场开始前启用季军赛。两场半决赛的胜者进入冠军赛，负者进入季军赛。两场比赛共用决赛轮的时钟、BO、FT 和时长，季军赛默认共用决赛题组，也可选择独立题组，其常规题组长度必须与决赛 BO 一致。

单击**生成对阵表**时，系统先检查设置，并列出缺少的内容。下午场开始前可以修改规模、种子和阶段规则。下午场开始后，规模、种子和公共设置固定。各阶段开放时，其题目、BO、FT 和时间设置随即固定，包括仍在等待选手排序的比赛。

| 字段 | 说明 |
| --- | --- |
| `seeds` | 按种子顺序排列的不同用户 ID，数量须为 2 至 128 之间的 2 的幂。第 1 轮中第 1 名对第 2 名、第 3 名对第 4 名，依此类推。 |

| `rounds[].tiebreak_seconds` | 必填，该阶段每个附加赛小局的时长，单位为秒，必须大于 0。 |
| `rounds[].break_before_seconds` | 必填，上一阶段所有比赛结束后，到本阶段开放前的休息秒数，必须非负，第 1 轮必须为 0。 |
| `rounds[].start_at_ms` | 整轮开始排序的 UTC 毫秒时间戳。新增或修改的时间必须位于未来和下午场时间范围内，各轮时间递增。 |
| `rounds[].post_order_wait_seconds` | 完整 180 秒排序窗口之后的准备秒数，默认 30。 |
| `rounds[].game_break_seconds` | 小局实际结算后，到下一常规小局或附加赛的间隔秒数，已排期阶段默认 60。 |
| `rounds[].match_extra_time_seconds` | 本轮每场对局的常规小局共享加时，省略时使用根级兼容值。 |
| `third_place` | `null` 关闭季军赛，`{"mode":"shared"}` 共用决赛题组，`{"mode":"custom","group_a":[...],"group_b":[...],"tiebreak":[...]}` 使用独立题组。 |
| `match_extra_time_seconds` | 兼容值，每场对局的常规小局共享的额外时间，必须非负，默认为 0。 |
| `penalty_seconds` | 每次错误提交对本常规小局后续提交增加的计分罚时，默认为 20，设为 0 可关闭。附加赛错误提交不罚时。 |
| `escalation_grace_seconds` | 等待卡住的评测的最长时间，超过后需由工作人员裁定。默认为 120。 |

### 修改未开放阶段

从比赛管理操作中打开**赛程与对阵**，可以修改尚未开放阶段的 BO、FT、题目列表、预约时间、小局时长及休息时间，然后单击**保存修改**。预约时刻到达时，上一轮必须已全部结束且最短休息已完成。若任一条件不满足，该轮显示**需要重新排期**并保持关闭，工作人员必须设置新的未来时间，系统不会自动顺延。若预约时刻已经满足条件，仅定时器延迟或重复送达，则仍沿用原定时钟。已开放阶段不可修改，编辑期间发生开放时，服务器会拒绝修改。

设置 API 同样接受完整设置请求中的这些修改。拥有 `contest:manage` 权限时，通过设置接口的 `GET` 请求可以读取当前配置及 `opened_rounds` 数量。只有下午场开始前可以修改对阵规模，比赛进行中不能增加或删除淘汰阶段。

插件重新加载时会升级已有对阵配置，保留种子、小局、比分和计时。已开放阶段保留原先打完全部常规小局的规则。尚未开放且未配置 FT 的阶段采用默认过半胜局数，并仍可修改。没有 `start_at_ms` 的旧阶段保留原有节奏，为未开放阶段补充排期后，才使用统一排序与准备时钟。

### 共享加时

在每轮中设置**每场共享加时**后，双方选手在一场对局的常规小局中共用这份额度。基础时间用完后自动进入加时，直到有人获胜或额度耗尽。选手不能跳过加时来保留额度。如果双方始终未通过，当前小局会消耗全部剩余加时，双方均不得分，后续小局只有基础时间。

例如，每局基础时间为 10 分钟，共享加时为 5 分钟，获胜提交在第 12 分钟提交，则消耗 2 分钟加时。下一小局仍有 10 分钟基础时间，最多再使用 3 分钟加时。未用完的基础时间不累积进额度。每场新对局重新获得完整额度，附加赛使用该轮配置的时长，不使用共享加时。

加时按获胜提交的实际提交时间结算，计分罚时和等待评测均不额外消耗额度。提交必须早于最终截止时间，加上罚时后的计分时间即使超过截止，仍可参与判胜。修改未来阶段不影响已开放阶段和正在进行对局的计时。

## 胜负规则

1. **排序。** 每轮到达配置的开始时间后，选手为对手排列题目顺序。排序窗口持续完整的 3 分钟，全部选手提前提交也不会提前结束。截止时采用最后一次有效排序，未提交的一方采用题组原始顺序。
2. **开始。** 排序结束后统一等待准备时间，默认 30 秒，然后该轮所有对局同时开始第一小局。
3. **小局。** 每个常规小局中，双方同时做各自的下一道题。对通过的提交比较实际提交用时加累计罚时，计分用时较少者获胜，与评测完成的先后无关；计分用时相同时，提交 ID 小者获胜。小局时间结束时双方均未通过，则双方都不得分。小局实际结算后，若整场比赛尚未结束，则等待配置的小局间隔，默认 60 秒，再开始下一局。常规小局进入附加赛、连续附加赛之间同样等待该间隔，但不再排序或额外准备。整场最后一局之后不追加小局间隔。
4. **结果。** 每个常规小局结束后，先达到 FT 的选手立即晋级，剩余常规小局不再进行。若双方均未达到 FT，则最多进行 BO 个常规小局，打满后胜局多者晋级。比分相同时（包括双方均未得分），双方做本轮第一道附加赛题目；附加赛无人得分时，改用下一道附加赛题目。

以 BO3 / FT2 为例，2 比 0 时两局即结束，2 比 1 时三局结束。无人得分的小局占用一局 BO，但不增加胜局数。打满三局后，1 比 0 晋级，1 比 1 或 0 比 0 进入附加赛。BO 和 FT 可分别设置，例如 BO5 / FT3。附加赛不计入 BO 上限。

附加赛按通过代码的实际提交时间比较，错误提交不增加罚时，与常规小局的罚时设置无关。实际提交时间完全相同时，提交 ID 小者获胜。

出现通过的提交后，小局会等待到后续提交不可能反超其成绩，或实际截止时间到达，再等待所有可能改变胜负的评测完成。计分罚时不缩短提交窗口，也不消耗共享加时。

胜者共同等待下一阶段开放。同一阶段的每场比赛使用该阶段的题目和时长。附加赛无人得分时，下一道附加赛题目仍使用该阶段的附加赛时长。同一阶段内各场比赛进度可能不同，因此应在有监考的场地进行。

## 比赛进行中

选手在**比赛主页**进行比赛。页面顶部为选手本人的比赛，显示当前所处阶段；轮到排序时显示排序列表，小局开始后显示当前题目和剩余时间。排序阶段可查看对手题组，正式作答时只显示当前自己的题目或共享附加赛题目，并隐藏题号。准备、小局间隔及整场结束后不显示题面。旧链接、样例和附件同样由服务器拒绝访问。阶段切换时清理题面缓存，编辑器草稿保留。选手只能向当前小局的题目提交代码。**排行榜**页面为选手提供返回本人比赛的链接。

**排行榜**页面采用左右镜像的横向树，分别从中间向两侧展开。中间上方为冠军赛，下方为季军赛，四个选手位置形成方形。实线表示胜者晋级，虚线表示半决赛负者进入季军赛。顶部只显示当前轮次和剩余对局数，赛程总览及编辑操作位于**淘汰赛管理**页面。每张对局卡片显示种子号、各小局的结果和当前小局的剩余时间，等待开始的比赛显示开始时间。单击**投屏**可全屏显示对阵表，同时隐藏仅供工作人员查看的统计信息。单击某场比赛，侧边面板显示比分、各小局的题目和胜者、双方的提交记录（可跳转至评测详情）以及工作人员操作。

工作人员在侧边面板中执行以下操作，每项操作执行前均需确认。

| 操作 | 可用时机 | 说明 |
| --- | --- | --- |
| **立即开始** | 未配置排期的旧对局等待排序时 | 在已开放阶段内开始该对局。已排期阶段不提供单场提前开始。 |
| **强制截止** | 小局进行中或等待评测时 | 立即重新判定当前小局，常用于重测之后。小局时间未到时不会提前结束。 |
| **判……获胜** | 小局进行中、等待评测时或比赛需要裁定时 | 判定该选手赢得本场比赛并进入下一轮。此操作不可撤销。 |

### 小局提醒

每局结果在页面中显示为持续通知，关闭后才消失。单击**启用桌面通知**，再用**测试通知**检查浏览器及系统权限。比赛窗口在后台时，小局结果还会触发桌面通知，供选手在系统通知中心查看。横幅显示时长由操作系统决定。连接中断后自动重连，不重复提醒已查看的结果。

## 评测延迟或出错

有更早的提交仍在评测时，小局不判定胜负，即使小局时间已经结束。此时比赛显示**等待提交评测完成**，评测结果出来后按正常规则判定。

评测在 `escalation_grace_seconds` 内仍未完成时，比赛状态变为**需工作人员裁定**，对阵表上方的统计栏计入该场比赛。侧边面板显示需要裁定的原因，提供卡住的提交的链接，并可直接重新评测。确认评测结果后，使用**判……获胜**裁定比赛。附加赛题目全部用完仍未分出胜负时，比赛同样需要工作人员裁定。

## 比赛结束后

到达下午场的结束时间后，不再开始任何比赛，无论是自动开始还是单击**立即开始**。此时仍在进行的小局无法再决出胜负，因为选手已不能提交；系统不会按双方均未得分处理，而是将比赛状态设为**需工作人员裁定**，侧边面板注明下午场已结束。若此时仍有提交在评测，系统先等待评测结果，与小局正常结束时相同。

结束时间到达前，对阵表上方的统计栏会提示工作人员，统计当前小局或计划开始时间超出结束时间的比赛数量。结束时间过后，统计栏改为显示尚未结束的比赛数量。逐场裁定这些比赛后，对阵表即完成。
