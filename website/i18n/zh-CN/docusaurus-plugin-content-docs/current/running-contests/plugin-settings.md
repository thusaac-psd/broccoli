# 插件设置

插件可以提供由管理区填写的设置项。根据设置项的不同，同一个值最多可以在四
个级别中分别配置，从覆盖整个服务器的值，一直到某场比赛中某一道题目的值。

## 四个级别

| 级别 | 覆盖范围 | 谁可以设置 |
| --- | --- | --- |
| 全局 | 服务器上的每一场比赛 | 插件管理 |
| 题目 | 一道题目，无论它出现在哪里 | 题目编辑 |
| 比赛 | 一场比赛 | 比赛管理 |
| 比赛题目 | 一场比赛中的一道题目 | 比赛管理 |

## 哪个级别生效

比赛题目的值优先于比赛的值，比赛的值优先于题目的值，题目的值优先于全局
的值。各级别逐个字段组合：一个级别只设定你在该级别保存过的字段，它没有设
置的每个字段都取自范围更广的下一个级别，直到插件的默认值。假设全局的编译
设置为 C++ 指定了 gcc-14，而某道题目只修改了 Python 解释器：这道题目编译
C++ 时仍然使用 gcc-14。

以冷却时间插件的提交冷却时间为例。某场比赛把它设置为六十秒，该比赛中的一
道比赛题目又把它设置为三十秒。这场比赛中的每道题目提交间隔都是六十秒，唯
独那道有自己单独设置的比赛题目，提交间隔是三十秒。

关闭一个设置项的道理类似。设置过开关的级别中最精细的那一个决定这个功能是开还是关，
全局级别最后考虑，无论范围更广的级别怎么设置。在比赛级别关闭某个设置项，即使题目级别
保持开启，整场比赛的这个设置项依然是关闭的，其取值也回退为全局的取值。

对于你没有设置的每个字段，表单会显示插件实际使用的值以及它来自哪个级别，包括全局的值。
服务器按照插件读取设置时所用的同一条规则得出这些值，因此表单显示的就是评测时使用的。

## 在哪里设置

在管理区打开插件页面，选择某个插件，再打开它的设置。即使还没有保存过任何
值，表单也会显示这个插件的设置项，因为表单的结构来自插件本身，而不是来自
已保存的记录。比赛和比赛题目的值要在比赛自己的设置里配置，而不是在插件页
面配置。

:::note[默认值不会被保存]

你没有设置过的级别会保持默认值，不会覆盖范围更广的级别。只有你保存过的值
才算是已设置。

:::

## 服务器拒绝的值

每个设置项都有类型，通常还有取值范围，服务器会在保存时检查每一个值。类型错误、超出范围或不在
可选项之中的值不会被保存，表单会标出服务器拒绝的字段。因此，已保存的值总是与表单显示的含义一致。

插件还可以对照服务器上的其他数据检查一个值：子任务的测试点是否存在、资格赛的晋级名额是否
够其题目使用。这类检查从不拒绝保存，因为需要修改的可能是测试数据或题目。它会作为题目或比赛的
配置问题列出，直到其中之一发生变化。只有值本身就有错误时，保存才会被拒绝，例如两个子任务同名。

如果你所用的服务器上没有加载某个插件（插件在那里加载失败），这台服务器就无法得知插件会如何评价
这些设置。此时配置问题会提示你稍后重试，而不是显示没有问题；该插件检查的题目会一直被标记为存在
问题，直到一台加载了该插件的服务器完成检查。
