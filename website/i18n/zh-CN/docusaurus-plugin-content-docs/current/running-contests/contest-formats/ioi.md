# IOI 赛制

该赛制把每道题目的总分建立在子任务之上，并支持部分得分。它还可以配置令牌
（token）和分级反馈。

以下设置分为两个作用域。比赛级别的设置在 `[config.contest]` 下，每场比赛
配置一次。题目级别的设置在 `[config.task]` 下，按比赛题目分别配置，因此同
一道题目在不同比赛中可以使用不同的子任务划分。

## 子任务

一道题目在 `[config.task]` 下被划分为若干子任务。每个子任务都有名称、评分
方式、满分，以及它所覆盖的测试点标签。

| 键                | 默认值  | 含义                             |
| ----------------- | ------- | -------------------------------- |
| `name`            | Subtask | 展示给参赛者看的名称              |
| `scoring_method`  | group_min | group_min、sum 或 group_mul     |
| `max_score`       | 100     | 该子任务满分对应的分值             |
| `test_cases`      | 空      | 该子任务覆盖的测试点标签           |

测试点的标签就是给该测试点设置的标签，若没有设置，则使用它的数字 ID。

- `group_min`，只有子任务内的每个测试点都通过，才能拿到满分，否则得零分。
  这比 CMS 的 GroupMin 更严格，后者会按子任务内最低的测试点得分对其缩放，
  因此在这里一个得半分的测试点会让整个子任务归零，而在 CMS 下只是减半。
- `sum`，子任务按通过的测试点比例给部分分，并按每个测试点各自的分值加权。
- `group_mul`，子任务把各测试点的得分比例相乘，因此一个表现差的测试点会拖
  累整个子任务。

题目的总分是其所有子任务得分之和。如果题目没有配置子任务，会自动生成一个
名为 All Tests 的 `sum` 子任务，覆盖所有非样例且分值大于零的测试点，其满
分等于这些测试点分值之和。

子任务内的部分得分只有在检查器把某个测试点判为小数分数时才会出现，例如一
个会汇报得分的 testlib 检查器。内置的比较器都是全部通过或不通过。

## 跨提交的评分

`scoring_mode` 是一项比赛设置，决定参赛者某道题目的分数如何在其所有提交中
选取，默认值为 `max_submission`。

- `max_submission`，取该参赛者所有提交中总分最高的一次。
- `sum_best_subtask`，对每个子任务分别取所有提交中出现过的最高分，再把这
  些最高分相加。
- `best_tokened_or_last`，即经典的令牌规则，取已使用令牌的提交中的最高分
  与最后一次提交得分中的较高者。

## 反馈

`feedback_level` 是一项比赛设置，决定参赛者在使用令牌之前能看到自己提交结
果的多少内容，默认值为 `full`。

| 值                | 展示的内容                                                    |
| ------------------ | -------------------------------------------------------------- |
| `full`             | 判定、总分，以及每个测试点各自的判定、得分、用时和内存         |
| `subtask_scores`   | 判定、总分，以及每个子任务的得分，但保留单个测试点的结果不展示 |
| `total_only`       | 只有判定和总分                                                  |
| `none`             | 不展示任何结果信息                                              |

:::note[子任务得分详情在哪里展示]

`subtask_scores` 多出来的详情会出现在题目的子任务列表、排行榜中每道题目的
得分，以及提交的子任务得分接口中。提交详情页本身在低于 `full` 的每个级别
都会隐藏各测试点的结果。

:::

## 令牌

使用一个令牌可以解锁某次提交的完整反馈，不受 `feedback_level` 限制。参赛
者只能在比赛进行期间对自己的提交使用令牌，且同一次提交只能被使用一次令
牌。

`tokens.mode` 决定令牌的运作模式，默认值为 `none`。

- `none`，关闭令牌功能，反馈始终按照 `feedback_level` 展示。
- `fixed_budget`，参赛者一开始就拥有固定数量的令牌，之后不再增加。
- `regenerating`，参赛者的令牌数量会随时间增长，直到达到上限。

| 键                            | 默认值 | 含义                     |
| ------------------------------ | ------ | ------------------------ |
| `tokens.initial`               | 2      | 参赛者比赛开始时拥有的令牌数 |
| `tokens.max`                   | 5      | regenerating 模式下的令牌上限 |
| `tokens.regen_interval_min`    | 30     | 每次新增一个令牌所需的分钟数 |

`tokens.max` 在 `fixed_budget` 模式下不起作用，该模式下的令牌数量在整场比
赛中始终维持在 `tokens.initial`。

## 排行榜

`scoreboard_visibility` 决定比赛进行期间谁能看到完整的排行榜，默认值为
`admins_only`。比赛结束后，无论这项设置为何，每位参赛者都能看到完整排行
榜，组织者则始终能看到。

| 值                     | 含义                                                             |
| ----------------------- | ----------------------------------------------------------------- |
| `admins_only`           | 比赛进行期间只有组织者能看到完整排行榜，其他人只能看到自己那一行，且不显示名次 |
| `all_contest_viewers`   | 比赛进行期间所有能访问比赛的人都能看到完整排行榜                 |

每道题目都带有一个得分时刻，即参赛者拿到该题目分数所对应的、从比赛开始算
起的用时。`scoreboard_tiebreaker` 依据这些每题的用时来决定总分相同时的排
名顺序，默认值为 `max_score_time`。

| 值                | 含义                                                       |
| ------------------ | ------------------------------------------------------------ |
| `equal_rank`       | 分数相同的参赛者并列排名                                     |
| `sum_score_time`   | 按每道题目得分时刻之和打破平局，总用时更短者排名更靠前         |
| `max_score_time`   | 按单道题目中最大的得分时刻打破平局，用时更短者排名更靠前       |
