# ICPC 赛制

该赛制依据解出的题目数量为参赛队伍排名，并以罚时打破平局。每道题目要么全部测试点
通过，要么不算通过，没有部分得分。

## 设置项

以下五项设置均按比赛单独配置。

| 键                    | 默认值 | 含义                                            |
| --------------------- | ------ | ----------------------------------------------- |
| `penalty_minutes`     | 20     | 在通过之前，每次被拒绝的尝试所增加的罚时分钟数  |
| `count_compile_error` | false  | 编译错误是否计入被拒绝的尝试                    |
| `show_test_details`   | false  | 仅作提示用途，插件本身不会强制执行              |
| `public_standings`    | false  | 比赛期间参赛者能否看到所有队伍的排名行，而不是在比赛结束前只能看到自己那一行 |
| `freeze_minutes`      | 0      | 比赛结束前多少分钟排行榜停止公开更新            |

## 提交如何被判定

只有全部测试点都通过，提交才会被判为通过。判定在第一个未通过的测试点处停止，因此
提交在较早的测试点失败后，后面的测试点不会再运行。

没有测试点的题目会被判为系统错误，而不是白送的通过，因此配置有误的题目不会被意外
记为所有队伍都已解出。

## 排行榜如何排序

只要有一次提交获得通过判定，该题目即算解出。其罚时分钟数为
`floor(solve_time_ms / 60000) + attempts_before_solve * penalty_minutes`，
未解出的题目罚时为零。

队伍按解出题目数从多到少排名，数量相同时再按罚时从少到多排名。若两项仍然相同，则
依据队伍名称打破平局，而不是最后一次通过提交的时间。最先解出某道题目的队伍会在榜
单上高亮显示。

## 封榜

设置了 `freeze_minutes` 后，参赛者看到的排行榜会在比赛结束前这么多分钟停止更新。
封榜期间提交的判定会显示为等待中，而不是真实判定，直到榜单被解封。组织者始终能看
到真实榜单，无论是否封榜。

只有在 `public_standings` 开启时封榜才有意义，因为关闭公开排行榜的参赛者本来就只
能看到自己那一行，而这一行永远不会被冻结。

:::note[封榜后的解封]

比赛结束后，组织者可以在排行榜页面解封榜单；比赛结束前服务端会以 409 拒绝。解封会
把所有被冻结的提交还原为真实判定。一次解封只针对当时生效的封榜时间窗口：若之后修改
比赛的开始或结束时间，或修改 `freeze_minutes`，榜单会重新冻结，直到再次解封。

:::
